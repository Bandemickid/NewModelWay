# WayForPay — запуск

Ця версія потребує серверного Next.js на Vercel. Завантаження статичної папки в public_html не запускає API оплати. Основний домен потрібно буде підключити до Vercel після погодження. Push і деплой не виконані.

У Vercel → Settings → Environment Variables та локально у .env.local:

- WAYFORPAY_SECRET_KEY — секрет із кабінету WayForPay. Не передавати у чат; не використовувати NEXT_PUBLIC_.
- WAYFORPAY_SITE_URL=https://newmodelway.com — база returnUrl і serviceUrl. Для окремої тестової Vercel-адреси вказати її повний https URL. Вебхук має бути доступний без Vercel Deployment Protection.
- WAYFORPAY_TEST_AMOUNT=1 — тимчасово для перевірки. Це справжня оплата на 1 грн, не банківський sandbox. Прибрати змінну після перевірки та повторно розгорнути сайт.

Merchant account фіксований: newmodelway_com. merchantDomainName фіксований: newmodelway.com, як у магазині. Не змінюється автоматично на vercel.app.

Після налаштування змінних повторно розгорнути сайт, натиснути оплату кожного тарифу, перевірити суму 1 UAH, успішне повернення та серверний запис WayForPay Approved у Vercel Logs. Скасована оплата не повинна показувати успіх. Підтвердження замовлення обробляє вебхук /api/wayforpay/webhook.

Тарифи змінюються о 00:00:00 28.11.2026 за Києвом (27.11.2026 22:00:00 UTC). Браузер надсилає лише назву тарифу. Сервер встановлює суму, валюту та товари.

Приклад рядка Purchase без секрету (ілюстративне замовлення):
newmodelway_com;newmodelway.com;nmw-pro-1795773600-example;1795773600;14900;UAH;NEW MODEL PRO;1;14900

Порядок: merchantAccount;merchantDomainName;orderReference;orderDate;amount;currency;всі productName;всі productCount;всі productPrice.
Документація: https://wiki.wayforpay.com/en/view/852102
Наведений у документації результат HMAC має неузгодженість; реалізація перевірена незалежним відомим HMAC-MD5 вектором, порядком полів, підміною суми та підпису.

Перевірки: npm run build; node tests/wayforpay.cjs.

SendPulse: lib/wayforpay.ts → sendOrderToSendPulse — поки заглушка. Надсилання доступу/листів ще не реалізовано. Перед підключенням видачі доступу зберігати замовлення та ключ orderReference у стійкій базі, щоб повторні вебхуки не дублювали дії. Зараз повторні повідомлення можуть повторювати записи у логах. ПІБ буде порожнім, якщо WayForPay його не передасть; email/телефон також залежать від даних платника. Логи містять контактні дані, доступ до них має бути обмежений.

Повернення у браузері перевіряє підпис та Approved, потім віддає 303. Сторінка thank-you інформаційна і не видає доступу. Фактичне підтвердження — підписаний вебхук. Реальна оплата ще не виконувалась: потрібні ваш секрет у середовищі й погоджений деплой.
